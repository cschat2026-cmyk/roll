## Product Critique And Fixes
- Problem: ROI had extra inputs for window/board/boost, but those inputs did not fully change the later plan.
  Fix: ROI context now adjusts estimated dice cost and reward value, renders a strong/playable/weak decision meter, saves the context, and sends the selected spend window, verdict, stop line, reserve, cost, reward, and net value back to the dashboard.
- Problem: saving ROI could still leave the homepage acting like the player should push, even when ROI said wait or stop.
  Fix: the homepage plan now respects saved ROI verdicts. A saved stop verdict forces a hold recommendation; a saved wait verdict routes the player back to event/window confirmation before raising multiplier.
- Problem: the hero did not immediately explain the current plan state.
  Fix: added a three-part command strip for current next action, reserve floor, and spend window so returning mobile users can scan the useful status before opening deeper tools.
- Problem: ROI target options were too generic to support decision-making.
  Fix: target options are now labeled safer/current/high-value and show reward, adjusted value, estimated cost, and net value using the current window/board/boost context.
- Problem: several controls looked useful but did not change a later decision, especially event prep, ROI completion, and sticker sync.
  Fix: rebuilt the dashboard route around explicit blockers: claim dice, finish Quick Wins for the current game day, choose one confirmed spend window, then save ROI/stop-line data.
- Problem: Quick Wins could be confused with a spend trigger and daily checklist timing could drift by user time zone.
  Fix: Quick Wins now uses the 13:00 UTC game-day reset anchor, shows local reset time and time zone, resets checklist/watch confirmations on game-day rollover, and is excluded from spend-trigger buttons.
- Problem: old or repeated dice links could stay marked claimed forever even when the link version changed.
  Fix: claimed dice state is now keyed by URL, expiry, and dice value; expired inactive IDs are pruned and claimed links can be undone.
- Problem: sticker planner sync erased the selected event trigger, breaking cross-feature continuity.
  Fix: sticker/vault pressure now syncs back to the dashboard without deleting the chosen spend window.
- Problem: ROI push action marked a nonexistent checklist item.
  Fix: ROI push now saves the target, stop line, reserve, multiplier, and dice bank back into the dashboard.
- Problem: community watch items could be treated like real spend triggers, especially for returning users with old saved state.
  Fix: watch-only events no longer count as confirmed windows and cannot become the dashboard trigger; they are preparation prompts only.
- Problem: Puppet Party had only 40 milestones, making ROI look serious while hiding deep rewards.
  Fix: expanded to a full 62-step public ladder with source URL and coverage note, then rebuilt seed data.
- Problem: player-facing copy still exposed internal placeholder wording.
  Fix: rewrote milestone guidance into useful player advice and removed stale fallback content.
- Problem: mobile event/ROI pages had horizontal pressure from long Chinese text, tags, dates, and action buttons.
  Fix: added CJK title constraints, stacked mobile chips/tags/buttons, and hardened card text wrapping.
- Problem: static fallback showed stale May 19 data if JS was slow or unavailable.
  Fix: replaced stale fallback values with neutral/current-safe labels and refreshed sitemap lastmod to 2026-05-21.
