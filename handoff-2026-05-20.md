## What Was Fixed Today

- Reframed the product around real player loops:
  - Free dice -> mark claimed -> apply to dice bank -> ROI/dashboard.
  - Events -> watch trigger window -> dashboard timing.
  - Stickers/vault/gold block -> reserve advice -> dashboard.
  - ROI -> save target/stop line -> dashboard.
- Fixed free dice apply flow:
  - Mark all dice and apply to plan now changes default dice bank from 1200 to 1250.
  - Applied claimed links are tracked to prevent double counting.
- Fixed ROI save loop:
  - ROI inputs now save back to dashboard.
  - Dashboard now explicitly shows saved ROI target, dice bank, stop line, and reserve.
  - Tested with target 900, dice 1500, stop line 800, reserve 300.
- Fixed sticker linkage:
  - Missing stickers and gold-blocked state save back to dashboard.
  - If gold-blocked, dashboard trigger is Golden Blitz instead of being overwritten by Sticker Boom.
  - Trade queue entry persists and affects sticker pressure.
- Improved event linkage:
  - Watching an event sets the dashboard trigger.
  - "Watch best" creates a usable timing hook instead of a dead state.
- Improved internationalization:
  - Dynamic dice links, event names, event advice, statuses, filters, and milestone rewards are localized for English, Simplified Chinese, and Traditional Chinese.
  - i18n completeness currently passes: 504 keys in each language, no missing keys.
- Improved mobile layout:
  - Fixed mobile hero title clipping.
  - Fixed hero metrics overflow on 390px width.
  - Mobile quick actions and cards now fit without horizontal scroll.
- Removed confusing/internal-facing copy from visible UI where found.
- Rebuilt seed data after i18n/data changes.

## Known Remaining Issues / Risks

- The site still uses seed/static data for live game content. For long-term user trust, tomorrow's most important work is a real update pipeline or a practical manual-refresh workflow for:
  - Free dice links.
  - Event windows.
  - Sticker Boom / Golden Blitz timing.
  - Source labels and update log.
- AdSense and analytics IDs are placeholders:
  - `ca-pub-REPLACE_ME`
  - `pub-REPLACE_ME`
  - `G-REPLACE_ME`
  These are intentional placeholders, not old-domain residue. Use `tools/configure-site.mjs` before production.
- Current Monopoly GO data should be rechecked against fresh public/official sources before launch, because reward/event timing changes daily.
- Product still needs one more "real player usefulness" pass:
  - Are next actions too many?
  - Are dashboard decisions clear enough after the first visit?
  - Does the player understand what changed after saving from each page?
  - Are ads visible but not annoying on mobile?
